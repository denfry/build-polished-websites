# Anti-slop review

Slop is a default applied without a reason. Gradients, cards, glass, rounded
corners, bento grids, and animation are all legitimate when the thesis calls
for them. This review does not ban techniques; it asks you to justify defaults.
Run it on the plan before building and on the result before reporting.

For each category, answer the questions in writing. "Because it looks modern"
or "because sites usually do this" is a failed answer.

## Layout slop

Symptom: hero → three features → proof → pricing → FAQ → CTA regardless of
archetype; centered everything; every section the same height rhythm.

- What is the first content unit on screen, and does the archetype call for it?
- Which section could be removed without the user losing anything? Remove it.
- Where does the rhythm change on purpose, and what does the change signal?
- If a competitor's copy were pasted in, would the layout still make sense?

## Copy slop

Symptom: "revolutionize", "unlock", "seamless", "supercharge", "elevate",
"next-generation", "empower", "journey", headlines that describe a category
instead of the product.

- Can each headline be verified or demonstrated by something on the page?
- Does the copy use the product's own nouns and verbs?
- Which sentence would the actual team be embarrassed to say out loud?
- Was supplied copy preserved unless rewriting was requested?

## Component slop

Symptom: everything inside a rounded card; pills for every label; icons in
tinted squares; three equal columns for unequal content.

- Which components contain content of equal weight? Only those may be uniform.
- What does the container add: grouping, interactivity, separation? If none,
  remove the container.
- Do the controls look like the platform's native controls where users expect
  native behavior?

## Decoration slop

Symptom: gradient blobs, glows, dot grids, noise, glass panels, gradient text,
"abstract 3D" without a meaning.

- What does each decorative element communicate about this product?
- Would removing it improve legibility or hierarchy? Then remove it.
- Is the effect derived from the product world (material, print, signal,
  terrain) or from other websites?

## Social-proof slop

Symptom: invented logos, testimonials, ratings, "trusted by 10,000 teams",
awards, press mentions, or team photos.

- Is every claim, number, name, and logo supplied by the user or verifiable
  from the project? If not, it does not ship.
- When proof is genuinely missing, is the absence handled honestly (omitted, or
  a clearly marked placeholder in a draft)?
- Are stock photos of people implying a real team or real customers?

## Interaction slop

Symptom: scroll-reveal on every element, parallax, hover tilts, typewriter
headlines, animated counters, motion that delays content.

- What does each animation tell the user: state change, spatial relationship,
  progress, or nothing?
- Does content appear without motion when reduced motion is preferred?
- Does any effect delay reading or the primary action?

## Mobile slop

Symptom: desktop layout stacked vertically; three-column cards becoming a long
scroll; navigation hidden behind a hamburger with no priority; giant headline
that fills the phone screen.

- What is the mobile first screen, and was it composed on purpose?
- Which desktop elements were reordered, resized, or removed for mobile?
- Are primary actions reachable within the first screen and by thumb?

## Dashboard slop

Symptom: identical KPI tiles; sparklines as decoration; charts without units,
baselines, or time ranges; no empty, loading, or error states.

- Which single metric or task matters most, and is it visually dominant?
- Does every number show its unit, time range, and freshness?
- Does every data view have loading, empty, error, and permission states?
- Can the user act on what they see, or only look at it?

## Ecommerce slop

Symptom: attractive home page, but product, variant, cart, and checkout states
are missing or fake.

- Does the product page handle variants, price changes, unavailability,
  quantity, and errors?
- Does the cart handle edits, empty state, and the checkout boundary?
- Is shipping, returns, and payment information reachable from the product?

## Final question

Name the three decisions that make this site belong to this product and not to
any other. If you cannot, the review has failed regardless of how the page
looks.
